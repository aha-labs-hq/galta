# Names And Submitted Context

2026-09-21。本文拥有画布与对话命名、输入上下文、Codex 元数据同步的当前契约。

## 体验规则

1. 一张画布是一件独立作品，也是一个项目。画布名表达作品，对话名表达本次目的；名称不承担身份或文件路径职责。
2. 新对话无需命名表单。首次提交立即以请求摘要替换占位名称；首个成功回合结束后，在后台尝试一次语义命名。已有手动名称始终保留。
3. 只有未命名画布且请求主题明确时，后台命名才可给画布起名。问候和局部操作可以留下 Untitled canvas。自动名称确定后不随每条消息漂移。
4. 对话列表显示最新请求或未发送草稿预览。空白、未命名、未使用的对话不占列表；手动命名的空对话保留。连续新建复用当前未使用的空对话。
5. 发送前显示当前画布或选区数量、显式参考图、可排除的来源网页。窄侧栏优先保留对话名称，模型设置收成带名称提示的图标。
6. 消息不自动附带画布或网页截图。选区表示目标，参考图表示明确附带的图片。需要判断外观时，代理调用 canvas_capture / browser_capture。
7. 消息下方可展开轻量上下文收据：发送时的画布名、目标 ID、参考 ID 和网页身份。不重复保存图片字节，也不宣称保存了当时所有页面内容。

## 权威与边界

| 状态 | 权威 | 同步边界 |
| --- | --- | --- |
| 画布身份、名称与命名来源 | WorkspaceBundle.project | 名称投影到 Codex project；projectId 和磁盘目录保持稳定。 |
| 对话名称、命名状态 | WorkspaceBundle.agentSessions | thread/name/set 发布；流式保存不能覆盖最新名称。 |
| 原生对话与推理历史 | Codex app-server | thread/read 恢复显示，保留本地上下文收据。 |
| Codex 项目绑定与已发布值 | codexProject / session 发布字段 | 幂等创建，thread/metadata/update 归属，只确认实际发布值。 |
| 选区与显式参考 | 发送前同步捕获 | 等待连接和执行租约后仍使用同一份目标与图片。 |
| 当前网页 | 浏览视图 | 提交固定 tabId 和 URL；绑定只 browser_check，URL 已变则不可用，后续文档变化由工具检查。 |

useConversationMetadata 独立于用户回合。项目发布使用每画布 Web Lock；命名在 IndexedDB 更新事务内领取，另有命名锁覆盖多窗口和重试。锁获取最多等待 5 秒。只有命名锁释放后仍未完成的尝试才标记为失败，其他窗口不会把进行中的命名显示成失败。关闭执行窗口后，剩余窗口识别中断并进行有界后台恢复。断线撤销排队任务及重试计时器，重新取得锁时也检查空闲状态；后台任务不阻塞下一条消息。

自动命名使用当前选定模型的临时结构化回合，读取有长度上限的首次请求和回复，低思考强度，45 秒期限；会额外使用少量模型额度。MCP、应用、执行、看图、浏览和目标工具关闭；协议仍声明的 request_user_input 由客户端拒绝。临时回合不写入用户会话、不进入列表。失败保留请求摘要，每次连接最多补一次后台重试；同步、命名与中断恢复分别维护重试计数，不互相增加模型请求，不向用户提供重试任务。

命名结果与临时会话清理分别处理。已成功生成的名称不会因退订失败而丢弃；清理请求各有 3 秒期限，失败记录方法、会话/回合 ID 和错误，不替换原始推理错误。取消后晚到的启动响应仍触发对应清理，不重新调用模型。

同步失败与任务失败分开。项目 API 不可用时保留本地名称，记录诊断并进行一次有界后台重试；不显示同步告警、技术弹窗或手动重试按钮，不修改 Codex 数据库、不移动目录。恢复连接和名称变化可重新检查元数据。远端明确改名且本地没有未发布编辑时，项目读回或对话名称通知接受远端值；本地未发布编辑优先。本地改名会清除旧的发布确认，即使改回旧名称也视为一次编辑；远端读回复在存储事务内再次核对确认值与命名来源，名称通知则按事务中的当前状态判断本地是否有未发布编辑。重新打开原生对话也核对名称，不承诺跨设备冲突的严格时间排序。对话改名保存或取消后恢复按钮焦点，异步保存期间用户主动转移的焦点保持不变。

同步缓存只用于减少已完成状态的重复检查，不能替代实际发布确认。排队期间的连续编辑按最新保存值继续发布；失败记录对应实际尝试的名称，同步成功后清除旧失败记录。连续收到的对话改名通知在存储事务中依次判断是否有未发布编辑并应用，避免用通知到达时的旧 UI 快照丢弃后续名称。

Codex 归档状态由 app-server 管理。存在待发布的对话元数据时，先按画布目录分页读取归档会话，跨模型供应商识别归档记录；查询总期限 15 秒，响应或游标无效时停止发布。归档历史可以读取，但不能调用 `thread/name/set`；同步跳过该会话的名称与项目写入，保留本地历史、名称和未发布状态，继续其他会话。归档观察只保存在当前连接中，不写入 WorkspaceBundle，不伪造发布确认，也不自动恢复归档。名称变化、重新连接及原生恢复/启动通知会重新检查，恢复后发布积压的本地名称。

## 成本与性能

- 普通消息没有图片输入块；发送不调用 preview、图片编码或网页 DOM 全量读取。
- 结构摘要列出视口内最多 80 个对象，加选区与省略数量；使用现有 Excalidraw 几何能力。
- 显式参考图在发送前同步固定不可变 Blob，由现有媒体 Worker 编码后按 UI 顺序发送 PNG/JPEG/WebP；空参考不启动编码 Worker。总 data URL 长度上限 32,000,000，超限明确失败；存储继续使用二进制资源。
- 元数据更新复用不可变快照及资源存储，不恢复编辑器、不重置撤销栈、不新增作品历史。
- 历史中的旧截图仍属于原记录；改变只作用于后续提交。

## 升级与验证

已有会话在打开或保存时识别旧 Moodboard / New conversation 占位，自定义名称保留。已知原生会话归入对应 Codex project。新路径来自实际执行租约；旧 thread.cwd 只在尚无绑定时用于恢复。导入新画布剥离原生绑定及发布标记，保留可读名称和对话。

用户 Codex 数据中的旧测试会话、无法与本地画布关联的历史目录，不自动删除或合并。今后原生验收使用独立 CODEX_HOME，只复制必要模型/供应商配置和私有文件认证，正常退出删除配置和认证副本。

验证入口：

- `bun test tests/conversation-metadata.test.mjs tests/codex-test-home.test.mjs tests/codex-kernel.test.mjs tests/canvas-boundaries.test.mjs tests/source-browser.test.mjs`
- `bun scripts/verify-conversation-metadata.ts`：已在 Codex 0.155.0-alpha.9.2 验证实际项目 API、原生归属、结构化命名协议及临时会话不进入列表。独立状态、本地 Responses 数据，无真实模型推理。
- `tests/browser/conversation-metadata.spec.ts`：生产 UI、真实 IndexedDB、可控 RPC；覆盖手动改名竞争、多窗口领取、失败重试和 1440/360 px 布局。
- `tests/browser/source-page.spec.ts`：真实打包扩展与 Chrome 消息，验证身份检查、按需读取、图片像素、操作和导航边界。

尚未验证：真实模型中文标题质量、本次改动在用户已安装扩展中的加载，以及手机 Codex Remote 是否采用项目显示名。协议成功不能代替客户端实际验收。公开 [app-server 文档](https://developers.openai.com/codex/app-server/) 与安装版本生成的实验协议共同约束兼容性；项目 API 仍需按目标版本验证。
