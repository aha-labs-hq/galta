# 多画布：独立工作的入口

日期：2026-09-20。状态：已实现，浏览器预览和独立 Chrome for Testing 资料中的真实 MV3 原生侧栏流程已验证。

用户已确认：**一个画布就是一个 project，各画布基本隔离。** 本文拥有当前多画布产品契约。实际验证范围与未完成项见 验证记录。

## 体验承诺

每件创作都有自己的地方。人可以开始一件新工作，也可以离开、再回来，继续原来的构图和思路。

例如，从“山间旅宿”切到“秋日刊物”，切换的是作品、素材、历史和对话的整套上下文。回到“山间旅宿”，看到原来的构图、视角和未发出的消息。网页仍然是随时可用的素材来源。

产品里统一称为“画布”。实现继续使用 projectId 作为持久身份，不另加一层 project → canvases。每张画布内部仍然拥有多个对话、历史版本和已保存方向。

## 归属与隔离

| 内容 | 归属与行为 |
| --- | --- |
| 图像、文字、笔触、布局、素材来源 | 属于画布；修改 A 不影响 B。 |
| 历史版本、已保存方向 | 属于画布；从历史继续仍在同一画布内。 |
| 对话、Agent 检查点、未发送消息、附带参考 | 属于画布及其中的对话；切换不把它们带入另一张画布。 |
| 视角与最近对话 | 随画布恢复；侧栏与完整视图转换继续使用已有视口交接语义。 |
| 当前选区、活动工具、原生撤销栈 | 属于打开的编辑视图；打开选择器不动它们。首版跨画布重新进入时保留历史，重新建立原生撤销栈，不承诺复原上次选区或工具。 |
| 登录与服务连接 | 属于 Galta；不用每张画布重新登录。既有画布恢复自己的模型与思考设置，新画布沿用当前设置作为初始值。 |
| 当前网页 | 属于这次浏览视图；切换画布不导航网页，也不因切换把页面收入新画布。 |
| Agent 浏览权限与输入上下文 | 绑定提交时的画布和来源页面；切换、关闭或失效后不能转向另一张画布或新的活动标签页。 |

这里的“隔离”是文档、上下文和操作归属的隔离。浏览器资料、账户、设备权限仍然共享；它不是安全沙箱或租户权限边界。

跨画布复用保留一个直白的方式：复制、粘贴。粘贴得到独立对象与可持久保存的资源，保留有用的来源信息；原画布之后修改或归档不影响副本。不建立隐式共享对象或跨画布同步引用。

## 导航：当前画布始终有名字

顶部结构为：`Galta  山间旅宿⌄  [展开 / 返回浏览]`。

Galta 保留品牌字样，画布名成为唯一的画布选择入口，接替现有仅供导入导出的词标菜单。新能力只增加一个可识别的工作名称。底部对话选择、Time Machine 和绘图工具继续各司其职。

选择器同时用于寻找画布和开始新工作：

- 顶部只保留画布标题和轻量的“新建画布”按钮，其下按名称搜索。搜索只查询名称，不在第一版搜索全部对象或对话。不再重复展示总数、Recent 标题或新建说明。
- 中间按最近打开排列画布。每行显示一张小预览、名称和最近打开时间，当前画布用淡底色与一个小勾标明，不叠加黑色圆点、侧边条或 Current 文案。菜单打开期间顺序固定，避免点击时跳动。
- 底部是一行：归档入口、On this device 和更多操作。更多操作收纳当前画布的重命名、复制、归档与导出，以及导入和升级备份。导入、导出因此多一次点击；列表里的常用寻找与切换保持直接。没有当前画布时，更多操作仍然提供导入。
- “已归档”在同一个选择器中展示可恢复的画布。

预览是画布的缩小图，帮助识别熟悉的构图，不从素材中随机挑一张封面。预览缺失时显示中性占位，列表和打开能力不依赖它。运行、保存失败等状态只有实际发生时才出现。

选择器跟随对话菜单的 Glass 材质：高光沿圆润边缘形成厚度感，柔和渐变和投影维持轻盈的体积。界面沿用中性色和原生 UI 字体：360 px 的首选宽度、12 px 菜单圆角、8 px 行圆角，名称使用 13 px 中等字重，日期使用可读的 11 px 辅助字。预览是 56 × 40 px 的小矩形，行高至少 56 px；触摸控件沿用 44 px 目标，行高和预览随之增大。选择器和更多操作继承 PopoverContent 的默认 Glass 材质，与其他浮层共用 tokens.css 的 glass-surface 配方；选中态沿用 menu 角色。组件只负责布局，不另造或覆盖材质值。

名称过长时截断，焦点提示和列表提供全名。侧栏内菜单限制在可用宽度和高度中；长列表内部滚动，高度不足时整个菜单也可滚动，导入和归档入口仍然可达。全画布与窄侧栏使用同一套信息结构。搜索后可以用方向键选择画布或按 Enter 打开首项，中文输入法确认不触发导航。Escape 先关闭更多操作，再关闭选择器，各自返回触发按钮；快速连续按键也按逻辑上的打开层级处理，不被正在淡出的子菜单吞掉。操作失败回到选择器并显示原因。

重命名自动选中原名称，保存与取消使用带提示的图标按钮；输入框内 Escape 取消此次改名并回到搜索。保存期间禁用相关输入和操作。菜单中统一使用 canvas，包括导入与导出，不向用户增加另一套 workspace 概念。

不设置强制启动首页。首次升级直接回到现有作品，之后重新打开 Galta 默认继续最近使用的画布。名称搜索和最近使用列表先覆盖日常规模；只有实际画布数量、查找行为证明需要时，再增加专门的总览。

## 核心动作

### 新建与命名

点击“新建画布”直接进入空白画布，默认叫“Untitled canvas”，无需先填表。名称可以随后修改；允许同名，身份由 ID 区分。名称不影响文件路径、历史或 Agent 连接身份。

首次明确创作主题可在成功回复后补全名称，手动名称优先；本地名称通过项目 API 发布到 Codex。具体规则见[命名与提交上下文](conversation-context.md)。哈希工作目录继续作为稳定身份使用。

空白画布提供简短提示：“Drag an image here, or ask Galta.”新画布拥有新的历史起点和空对话；模型与思考设置可沿用当前值，素材和上下文从空白开始。显式创建的空画布也持久保留，不因没有内容自动删除。

### 切换与恢复

点击目标后，检查当前文字或笔触编辑是否结束；未结束时提示用户先完成编辑。随后保存作品、视角和消息草稿，再加载并验证目标内容。目标可用后才更新名称、编辑器、对话与访问记录。

保存或加载失败，留在原画布并显示具体问题。不能先显示 B 的名称却仍接受写入 A，也不能用一张空白画布掩盖损坏的数据。连续点击多个目标时只保留一个进行中的切换，避免交错完成。

重命名、项目切换和侧栏展开／返回共用同一个导航边界，异步完成前不能交错切换身份；原生视图交接期间，作品和草稿也暂停编辑。操作失败后恢复原编辑视图。

同一画布另有窗口保存了新版时，离开一个未修改的旧视图不改变共享的当前版本或视角。选择历史版本只通过明确的“从这里继续”完成。草稿保存失败按对话分别记住，另一段对话成功保存不能解除它；重新编辑并成功保存该草稿后才允许离开。

首版跨画布切换保存所有作品版本，重新进入后从新的 Excalidraw 原生撤销栈开始。旧操作仍可以通过该画布的 Time Machine 查找和继续。仅打开或关闭选择器、搜索、重命名，都不能重置原生撤销栈。

这个取舍避免为了保留瞬时撤销状态而无限保活重型编辑器。若用户确实频繁往返并依赖逐步撤销，应先验证 Excalidraw 能否可靠保存、恢复完整 undo/redo，再决定增加有限数量的驻留视图；不能直接承诺无上限保活。

### 浏览器中的位置

每个已经打开的 Galta 视图固定绑定它的画布。A 窗口切换到另一张画布，B 窗口的工作不会跟着改变。

扩展入口首次打开、且没有明确目标时，最近使用画布只是导航默认值。完整画布地址以及侧栏与完整视图之间的交接必须显式携带 projectId。由此可以让两个完整标签页分别保留两件工作。

在同一浏览窗口采集素材时，浏览其他来源页面应继续当前正在工作的画布。不能因为切换网页标签就静默换一个素材落点。关闭后重新打开具体视图与新入口的恢复规则，应在原生 Chrome 侧栏中单独验证。

侧栏与完整视图交接保留可编辑区域中的作品中心和可见跨度。草稿与参考图恢复完成后才进行初始定位；浏览器面板改变尺寸时按实际可用区域保持这一视角。日常输入和选区变化保持画布位置与缩放，避免编辑中的构图漂移。

### 生成与导入期间

Agent 任务始终归属于启动它的画布。内置任务由扩展的 offscreen task host 持有，不依赖打开的编辑器；切换、隐藏或关闭视图只解除该视图的观察，任务继续执行。重开画布会恢复任务和待回答的问题，只有用户显式 Stop 才中断所选任务。

运行时可以重命名、导出、复制当前已保存的作品，或切换到另一张画布，不能把源任务带入副本或新项目。任务结果只提交到原项目。任务尚未交给后台 host 的本地准备阶段仍需要“停止并切换”或“留在此画布”；停止成功并保存终态后才切换，不得悄悄取消。

在连接或准备阶段停止也保留已提交的指令及停止状态，即使尚未启动模型请求。尚未保存的对话记录按对话保留，不能被下一次运行覆盖。

本视图连接了外部 Agent 时，需要先由其客户端结束连接才能切换，不替外部客户端发送停止。其他视图的任务不阻止本视图普通导航，但会阻止归档对应项目；原生注册表仍拥有项目执行排他权。

图片导入也有相同归属：进行中的导入完成后才切换，或显式“取消导入并切换”。迟到的图片和 Agent 结果都不能落入新画布。

后台任务不通过隐藏挂载所有画布实现。offscreen host 使用文档事务提交作品与终态对话；浏览器退出或扩展重新加载会结束 host。替换 host 将未完成记录标为中断失败，不自动重放任务。具体生命周期由 [架构](../architecture.md) 拥有。

### 复制、导入与导出

“复制为新画布”复制当前作品、当前资源和素材来源，生成新 ID、新历史起点与新对话，不复制旧的运行会话或未发送草稿。默认名称为“原名 · Copy”。这适合从已有构图开始另一件工作；历史中的“继续”则仍属于当前项目。

“导入画布”增加一张画布，无论文件 ID 是否与本地重复，都不会覆盖正在做的工作。导入时重映射 projectId 以及嵌入的提交、分支项目引用，保留作品历史和可读对话记录。源文件中的原生 threadId、checkpoint 和本地绝对路径不能自动成为新项目的可执行权限；新画布的下一次 Agent 请求建立独立会话。本地文件只有已打包的字节可以承诺迁移，不能承诺恢复另一设备的运行环境。

快照、历史关系、当前视角、模型设置和对话内容在创建前验证；失败不产生新项目，文件选择器关闭后仍显示错误。文件读取、格式、版本和内容失败在输入边界分类；产品提示说明下一步与原作品保留，诊断只记录稳定的操作 ID、项目 ID 与失败码，不显示或记录文件正文和解析片段。存储或运行环境失败不能伪装成损坏文件。

“导出此画布”导出当前画布的作品、资源、历史、保存方向和可读对话记录。现有未发送草稿存于独立数据库，不在当前 `.galta` 包中：这一边界直接显示在导出操作下，键盘与触摸用户不需要悬停。不要把该文件称为整套工作状态或机器环境的备份。

导出与重命名、复制、归档、恢复、导入、导航共用 `CanvasWorkspace` 的操作所有者。操作名是忙碌状态的唯一来源，界面只投影状态，不另造导出布尔值。导出先提交当前编辑内容，再将不可变工作区交给短期 worker 编码；后台任务继续运行，后续结果不改变已捕获的导出文件。文件编码期间禁止交错导航，进度留在画布选择器里，操作子菜单关闭也不丢失；失败解除占用并保留原视图与明确错误。

### 归档

首版用归档整理列表，提供可恢复路径。归档当前画布后回到最近使用的可用画布；没有其他画布时展示简洁空状态，提供新建或恢复。归档不清理素材、历史或原生运行文件；进行中的任务必须先结算。

恢复先在同一存储事务内校验实际保存的数据，再解除归档。损坏的画布恢复失败时，原内容和归档状态保持不变。

其他打开视图收到归档变化后停止编辑，并取消未完成图片导入。若它们已有尚未保存的笔触或布局，会作为历史版本保留，归档状态和默认打开版本不变；保留失败时明确要求保持视图打开，后续离开前再次保存成功才能切换。普通写入不能把归档项目重新写活。

### 删除

只有已归档的画布可以永久删除：先归档（可恢复），再从“已归档”删除。每行末尾的删除按钮删一张，更多操作里的“Delete N canvases…”删当前列出的全部；确认框写明名称、数量和“不可撤销”，取消则什么都不变。

删除一张画布会一并移除它的全部：作品、历史、资源、预览、视角、目录记录、对话、迁移备份、所有对话的未发送草稿、浏览窗口对它的记忆，以及 Galta 应用为它保存的工作目录和交付快照。

顺序决定安全：先在一个存储事务内删除浏览器中的记录，事务内再次核对归档状态，期间被恢复的画布原样保留、其他步骤都不执行；记录删除后才请原生宿主删除文件，最后删除草稿和窗口记忆。因此之后任何一步失败，最多留下一张已删画布的零散文件，绝不会出现画布还在、文件已没的情况；界面说明哪张画布的文件没能删除及原因（应用连不上、版本过旧、仍有视图或 Agent 在用、超时）。批量删除时，一张画布的记录删除失败会停在那里，已删除的保持删除。

原生目录按画布 ID 命名，相同 ID 的画布共用一个目录。每个浏览器资料的第一张画布都叫 `default-project`，它的文件永不删除，界面说明原因；从本资料复制出的浏览器资料也共用其余画布的目录，删除会一并删去。没有安装 Galta 应用时不删除任何文件；卸载应用后遗留的数据目录不在删除范围内。Codex 自己的线程与项目记录由 Codex 拥有，不在删除范围内。

## 实现与归属

- `CanvasWorkspace` 拥有目录、当前项目、全部画布操作的排他协调和离开确认。`CanvasSession` 只负责捕获、保存与导出本项目，菜单只发起操作和显示状态。每个 Session 固定绑定一个 projectId，切换成功后重新挂载；旧回调不能指向新项目。
- `IndexedDbWorkspaceRepository` 的 `galta-v1` 数据库版本为 4。`workspaces` 是文档权威；`canvas-catalog` 是轻量投影，与文档写入处于同一事务，记录名称、最近访问和缩略图。`canvas-views` 单独保存视角，平移和缩放无需读写历史；事务内核对 catalog 的当前版本和归档状态，拒绝旧页面覆盖新版本的视角。选择器不加载所有项目的历史图片。
- 缩略图由实际当前 head 生成，最大边 240 px。写入比较 head，旧任务不能覆盖新版预览；预览失败只保留占位，不阻止打开作品。
- `canvasLibrary` 处理新建、复制和导入。导入先检查快照与提交/分支图，再创建新项目；损坏导入不留下目录记录。
- URL 中的 `project` 固定完整标签页身份。同一浏览窗口的侧栏选择存于 `chrome.storage.session`；更换来源网页沿用该窗口当前画布。展开和返回的路径显式携带项目身份，返回时更新目标窗口的侧栏选择。
- 草稿仍按 `[projectId, sessionId]` 存储；`WorkspaceSync` 按 projectId 通知。账户连接信息可跨画布复用，原生线程和工作目录始终属于项目。
- 运行中的 Agent 持有项目执行生命周期锁，归档要求独占同一锁。停止切换等待已完成作品和终态对话保存；原生注册表继续负责 Agent 排他，不另造调度器。
- 导航仅在保存和目标验证成功后更新身份。创建已落库后，最近访问或浏览器偏好写入失败会作为独立提示呈现，不伪装成新建失败诱导重复创建。

projectId 是持久文档身份，canvasId 是一次已打开视图的连接身份。重命名更新注册标题；切换项目建立新连接。

升级直接把原 `default-project` 纳入目录，保留 ID、作品、历史、草稿、原生目录和会话。只在没有任何项目时创建默认画布；归档所有项目不会制造新默认作品。

文件夹、标签、跨项目共享引用、后台生成和云端同步不属于本次范围。跨项目素材复用采用明确的复制，后续修改各自独立。

## 验收必须发生在使用边界

- A、B 使用相同素材和同名对话：分别编辑、生成、撤销和回看历史，互不影响；副本不共享可变资源或原生线程。
- A 写一半消息并附带参考，平移缩放后切 B；返回及重开 A 后恢复其作品、视角、最近对话和草稿。
- 保存失败、目标损坏、快速连续点击、切换中关闭窗口：不出现名称与内容错配、不丢旧作、不重复创建。
- A 的导入或 Agent 工具调用在切换边界迟到：只按原身份成功提交，或明确拒绝，绝不写入 B。
- 两个窗口分别打开 A、B，导航独立；同一项目的跨窗口冲突仍遵守现有显式加载和分支保留语义。
- 导入同一个文件两次：创建两个独立项目，原作品保持不变；对话可以读，下一次执行不复用源项目的原生线程。
- 归档与恢复包含打开中的其他视图；归档最后一张画布有可用出口。
- 升级前后比较旧项目的快照、历史、草稿和会话引用，原项目身份不变。
- 使用实际图片与多历史版本验证目录只读取轻量摘要、按需读取当前画布；记录真实耗时和内存，再判断是否需要进一步优化，不预先宣称“秒开”。
- 在安装的 Chrome 扩展中验证 360/480 px 侧栏与完整画布的选择器、键盘、名称、项目交接和视口恢复；网页预览测试不能替代这一验收。
