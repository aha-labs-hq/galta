# 画布揭示与分组契约

日期：2026-09-30，落笔一节 2026-10-28 重写。本文拥有"一支笔落下之后画布如何让用户看见"以及"agent 应当如何组织它创建的元素"这两条当前契约。

## 体验承诺

一段工作落下时，用户应当看得见它在长，而不是被一整块结果砸中。一件交付物应当能被整块拿起、整块挪走，而不是散成几十个抓不住的碎片。

## 起因

在用户真实画布（Dia，projectId `project-209a7e47-e4e4-4774-b80c-89559e61c273`）上实测到两个缺陷。

**一、几乎没有任何可见过程。** 原实现在 `CanvasPresentation.show` 中要求 `el.type === 'freedraw'` 且 `el.frameId` 为空且底色透明，并且以"累计 32 ms"为总量预算，超预算即 `break`。三条限制叠加的后果是：文字、矩形、图片、箭头永远没有呈现过程；一旦元素进入 frame 就失去呈现；而超过预算之后的所有元素被直接丢弃。实测三次提交各 50 个元素，绝大多数元素没有任何可见过程。

**二、分组要求从未到达 agent。** 全仓唯一的分组指令位于 `packages/canvas/src/instructions.ts` 的 `CANVAS_INSTRUCTIONS` 常量内，而 `docs/agent-architecture.md` 早已记载该常量不是 MCP 实际下发的 payload。真正送达的 `GALTA_MCP_INSTRUCTIONS` 与嵌入式 `codexInstructions` 中没有任何分组要求。实测 150 个对象的 `groupIds` 全为空。

历史证据同向：`docs/evidence/detective-board-2026-09-18/observer-notes.md` 记录 agent 曾主动尝试使用 `groupIds`，被当时的 schema 拒绝，当时的评价就是"不应称模型没想到分组"。

**三、提交后的装饰仍然看不见过程（2026-10-28）。** 修复一之后的装饰把已经画好的元素再盖一份、再淡出：不透明笔画看不出任何变化，半透明笔画是一次加深的闪烁。西装猫的 4,749 笔因此一批批整块出现，Time Machine 里则在 0.14 秒内整体溶入。

## 一、落笔：原子提交，工作按叠放顺序落下

作品、修订号、历史、回执和撤销仍然在一次原子事务里完成。落笔不产生中间文档、不等待模型、不改变点序，也不移动实时画布的相机。实时画布与 Time Machine 共用一个实现，`apps/extension/src/canvas/inkPen.ts` 里的 `InkPen`。

- **落什么。** 一次编辑最上层、连续的那段新元素，按叠放顺序依次落下（`newWork`）。手绘笔画沿自己的点序从第一点画到最后一点；线条、箭头、形状和文字轮到时整体出现。图片（它的标题是 DOM，会先于图片出现）、frame 及其成员、网页和视频（DOM 覆盖层）在提交时出现，并截断这一段：它们之下的新元素也在提交时出现。因此等待中的元素从不压在已显示的元素之下，叠放始终是原生的。引擎不重排 agent 的工作。
- **怎么画。** 文档先提交，tile 暂不显示这些元素（`holdStaticElements`，见 `patches/README.md`）。笔在 tile 每次渲染的开头运行，返回它此刻呈现的元素；它们由同一个原生渲染器画在 tile 之上，落在 tile 的设备像素上。笔下那一笔是一份副本，轮廓只到笔尖：原生笔刷游标 `createFreeDrawPlayback` 增量算出前缀轮廓，交给 `presentFreeDrawElement`。已画完的元素以它本身呈现。交接因此不重叠、不闪、不移位，唯一的变化是一笔收尾的笔帽，就像手抬起时那样。
- **成批烘焙。** 画完的工作每 128 个一批烘进 tile，一遍画成，与呈现时完全一样。GPU 画布对交叠的半透明笔画做抗锯齿时，结果取决于一遍画多少笔：逐笔烘进，密集排线会比之后任何一次完整重绘深约一成（1× 下实测 +9%）；按 128 一批，落定结果在 tile 自身重绘的波动之内。未烘焙的工作一直以原生方式呈现，所以成批不改变用户看到的任何东西。
- **节奏。** 速度按路径长度推算，不是记录到的手速。`--motion-ink-pace`、`--motion-ink-lift` 和 `--motion-ink-catchup` 分别拥有速度、抬笔间隔和追赶预算，当前是每秒 600 屏幕像素、60 ms 和 6 秒。新编辑接在队列之后；队列过长就加速，使所有工作在预算内落完，后来的编辑不会拖慢先前的。减少动态效果把预算置零，作品在提交时出现。画面外的笔画轮到时直接出现，不占绘制时间：相机到达时它已经在那里。
- **打断。** 指针、键盘、停止请求、页面隐藏、切换到减少动态效果，以及其他来源的 apply（恢复、历史激活），都让工作立即落下。屏幕上正在呈现的，在下一次渲染里原样烘进；从未显示的，再下一次渲染交还，tile 原地重绘，保留现有像素直到新像素就绪，画布不会空白一帧。被撤销、删除或改写的元素不再由笔落下；被已显示的内容盖住的工作立即落下。写入失败从未进入场景，所以没有可落的东西。
- **读取不受影响。** 画布读取、保存、导出、agent 的 capture 和预览都读完整文档，从不读呈现，不会把半笔当作已提交的内容。

`staticTiles.js` 的每画布调度器（`staticSceneScheduler`）只持有最新的渲染请求。笔在渲染里请求下一帧；如果把捕获的旧场景重新排入原生节流器，新旧画面就会交替出现，表现为画完的笔画消失、撤销后留下残影。

## 二、分组：要求送达 agent，不由引擎代劳

**结构决定：引擎不做任何自动分组。** 不按批次、不按轮次注入 group id。

理由不是"实现成本"，而是职责：一次任务需要几个语义单元，只有 agent 知道。引擎按批次自动分组会把一个刻意拆分的交付物粘成一坨，而且会让"分组"从任务判断退化为数量推断。`docs/agent-architecture.md` 既有的 "never inferred from element count or tool-batch boundaries" 继续有效。

要求改为经**两处真正送达的通道**下发：

| 通道 | 落点 |
| --- | --- |
| 工具 | `canvas_edit` 描述、`groupIds` 字段描述（Zod 与 host schema 两份） |
| 系统提示词 | `codexInstructions`（嵌入式 turn）、`GALTA_MCP_INSTRUCTIONS`（MCP `instructions`） |

`GALTA_MCP_INSTRUCTIONS` 的首 512 字符是 Discovery 可见窗口，因此绑定、保留、工具清单与分组要求全部前置在第一段内，且该段自包含。

**措辞中必须包含"不要只靠嵌套"这一条。** `relatedElementIds` 的分组展开是**一跳**，不是传递闭包：它取目标元素携带的 group id，再加入所有携带这些 id 的元素，仅此一层（frame 子元素与绑定文本走定点循环，是传递的）。若 agent 用"内层卡片组 + 外层任务组"表达归属，`move` 带 `scope: 'group'` 只会展开一层，用户拖动时行为不符预期。因此要求明确：**同一交付物直接共享同一组 id**。

**回执如实报告未分组。** 指令送达不等于遵守，因此 `canvas_edit` 的回执在**本批创建了两个以上元素且无一成组**时给出 `notes` 条目。判定依据是这批工作本身，不是数量阈值，也不是批次边界：

- 单个元素不成组 → 静默。一个元素没有"整块"可言。
- 全部成组 → 静默。
- **部分成组 → 静默。** 一批里既有成组的交付物又有独立元素，是合法的混合工作；对它唠叨就是把判断权收回到引擎手里。
- 只有更新、没有创建 → 静默。改写既有元素的组织不是本规则的范围。

这条 note 不阻止提交、不代建分组、不改动文档，只把调用方原本只能从"字段缺失"推断的事实摆到台面上。它是**告知**，不是**强制**：分组仍然是 agent 的任务判断。

## 非声明

- 不改协议。实测 `packages/runtime/src/codex.ts` 只转发 `item/agentMessage/delta` 与 `item/commandExecution/outputDelta`，工具参数**没有** delta 通道。本方案不依赖参数流，也不试图引入它：流式应用会破坏原子性、revision 校验与"一次编辑一个撤销步"。
- 不引入第二个文档状态拥有者。落笔只是呈现，永不进入持久化、快照或撤销栈。
- 不做引擎侧自动分组。
- **不承诺模型必然遵守分组要求。** 送达与自检是两件事：测试能证明要求进入了模型的请求，回执的 `notes` 能让未分组这件事在下一轮可见，但两者都不能强制模型修正。这是本契约已知的、有意保留的边界——强制分组会把"一次任务需要几个语义单元"这个只有 agent 掌握的信息，替换成引擎的数量推断。

## 证据与验证

- `tests/browser/ink-pen.spec.ts`：落笔的全部承诺。生长与不闪；1× 与 2× 下笔后的墨迹从此不再改变，包括交接时（300、28,000、280,000 点，模拟与记录压力）；落定结果与完整重绘一致；手一碰全部落下且没有空白帧；后来的编辑接在后面；标注在它之上的笔画画完后才出现；后来盖上的形状在被盖的墨迹之后出现；相机移动时呈现跟随；撤销不留残影；其他 apply 立即落下；1,500 笔在追赶预算内落完；停止、隐藏、减少动态效果与保存失败。可选的 `GALTA_INK_REPLAY` 用私有作品重放，不把作品存进仓库。像素一致性一律用截图判断：Chromium 会把频繁读回的画布改成软件渲染，读回会测到用户看不到的渲染器。
- `tests/browser/history-browser.spec.ts`：Time Machine 的一步只新增笔画时，笔就是它的光；Play 等墨迹画完；暂停立即落下；导出视频的中间帧里有正在生长的墨迹。
- `tests/browser/progressive-write.spec.ts`：大编辑分批准备、只保存一次、撤销和重做是一步；中断的写入什么都不提交，也什么都不显示；混合交付物整体落下、是一步撤销、可整组移动。`bun scripts/verify-progressive-write.ts` 测量准备阶段与长任务，以及准备期间收到的停止。
- `tests/brush-playback.test.mjs` 逐条比较笔刷游标与原生轮廓的绘制指令；`tests/static-scene-scheduler.test.mjs` 覆盖调度器的三条边界。测量记录见 docs/evidence/ink-pen-launch-2026-10-28/README.md。
- `tests/mcp-execution.test.mjs` 断言首 512 字符包含 `groupIds`；`scripts/verify-input-context.ts` 断言分组要求出现在真实模型请求的两个通道中。
- 既有分组断言不重复造：`tests/browser/canvas-semantics.spec.ts` 覆盖嵌套组写入/读取/恢复/取消分组与 `scope: 'group'` 位移，`tests/browser/box-selection.spec.ts` 覆盖原生组选择与 frame 归属。

## 边界

- 一跳分组展开是既有行为，本次**未修改**，只是通过指令措辞规避其影响。若要支持嵌套归属的整组拖动，那是 `relatedElementIds` 的独立改动。
- 只有手绘笔画有绘制过程；线条、箭头、形状和文字轮到时整体出现，图片、frame、网页和视频在提交时出现。
- 落定结果与完整重绘的差异在 GPU 抗锯齿本身的波动之内，不是逐像素相同：两次完整重绘在不同速度的机器上也会因一遍画多少笔而略有不同。
- 未在 120 Hz 屏幕上验收。
- 首 512 字符窗口是硬预算。新增要求时必须同时压缩既有措辞，不能靠延长首段解决。
